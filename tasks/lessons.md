# Lessons

- [2026-09-01] Prisma 7 + SQLite dans une image Docker sans accès réseau au runtime : `prisma migrate deploy` télécharge le binaire `schema-engine` à la volée si absent du cache. Règle : pré-chauffer le cache (`npx prisma generate && npx prisma migrate deploy` contre une DB jetable) dans le stage `deps`, pendant que le build a encore accès réseau, avant de copier `node_modules` vers le stage final.
- [2026-09-01] Sur une base `bookworm-slim` sans `openssl` installé, Prisma ne détecte pas la version d'OpenSSL et se rabat sur une cible de binaire incorrecte (`openssl-1.1.x` au lieu de la vraie cible bookworm/3.0.x), ce qui déclenche un nouveau téléchargement raté. Règle : toujours installer le paquet `openssl` dans les images utilisant Prisma sur Debian slim.
- [2026-09-01] Un volume bind-mount (`./data:/app/data`) est créé par Docker en root la première fois ; un conteneur qui tourne déjà en utilisateur non-root ne peut pas y écrire (`unable to open database file`). Règle : garder le conteneur root au niveau de l'ENTRYPOINT, `chown` le point de montage au démarrage, puis descendre en utilisateur applicatif via `gosu` avant d'exécuter les migrations/le serveur.
- [2026-09-01] Les pages Next.js qui lisent des données live en base (Server Components sans `cookies()`/`headers()`) sont prérendues statiquement par défaut au build — elles figeraient la donnée du moment du build. Règle : ajouter `export const dynamic = "force-dynamic"` sur toute page dont le contenu dépend de l'heure courante ou de données mutables en base.
